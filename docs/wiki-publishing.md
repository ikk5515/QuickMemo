# 위키 작업공간과 공개 주소

`/wiki`는 로그인한 계정의 개인 메모를 탐색하고 편집하는 작업공간입니다. 활성 계정의 메모 이용 권한과 암호화 키 잠금 해제가 필요합니다. 메모 화면과 같은 Live Editor, 암호화 저장, 충돌 확인, 이미지 처리와 이력을 사용합니다. 공개 위키는 별도의 읽기 전용 화면입니다.

## 하나의 공개 위키 주소

**위키 공개 설정**에서 주소와 공개할 폴더·개별 메모를 선택하고 내용을 확인한 뒤 공개합니다. 사용자의 공개 위키는 하나의 고정된 내부 식별자를 유지하며, 방문자 주소는 `/wiki/{slug}`입니다. 여러 폴더나 메모를 추가해도 새 위키나 임의 주소를 만들지 않습니다. 문서 링크는 같은 주소 아래 `?page=공개된/문서/경로`를 사용합니다.

주소는 앞뒤 공백을 제거하고 ASCII 소문자로 변환합니다. 영문 소문자·숫자·하이픈 3–40자이며 처음과 끝은 영문 또는 숫자여야 합니다. 예약된 경로명, Unicode와 URL 구조를 바꾸는 문자는 거절합니다. 서버의 원자적 claim과 사용자 root 연결로 중복 등록을 막습니다. 주소를 변경하면 이전 주소는 열리지 않으며, 다른 사용자가 이전 주소를 재사용할 수 없습니다.

기존 `/wiki/public/:wikiId` 주소와 게시 데이터는 유지합니다. **기존 위키 가져오기**로 선택한 위키의 최신 버전과 공개 범위를 확인하여 새 주소에 연결할 수 있습니다. 주소만 저장하면 기존 공개 복사본을 유지하고, 범위 게시에는 다시 동의해야 합니다. 공개 범위를 다시 확인하여 게시하기 전에는 원본을 편집하거나 작업공간을 다시 열어도 자동 반영하지 않습니다. 다른 기존 위키는 변경하지 않습니다. 연결된 기존 주소로 접속하면 새 주소로 안내합니다.

## 공개 범위와 자동 반영

공개는 명시적으로 선택한 범위에 대한 허용입니다. 폴더 선택에는 하위 폴더와 이후 추가되는 메모가 포함됩니다. 개별 메모 선택은 해당 메모만 공개 위키 최상위에 표시합니다. 다른 소유자의 메모와 휴지통 항목은 게시할 수 없습니다. 새 최상위 폴더나 별도 메모를 공개하려면 공개 설정에서 추가로 선택해야 합니다.

공개 내용은 원본과 분리된 복사본입니다. 원본의 암호화 본문과 키는 유지합니다. 소유자가 로그인·잠금 해제한 작업공간에서 저장이 끝나면, 선택한 범위의 변경을 모아 같은 위키에 자동 반영합니다. 입력 중이거나 저장·이미지 처리가 끝나지 않은 내용은 게시하지 않습니다. 동일한 저장 내용은 업로드하지 않고, 다른 탭의 공개 중지나 설정 변경은 서버 버전 검사로 보호합니다. 작업공간이 닫혀 있거나 잠겨 있으면 마지막 게시본을 유지하며 다음 활성 작업공간에서 변경을 확인합니다.

**공개 중지**는 서버에서 기존 공개 링크의 접근을 차단합니다. 이미 방문자가 저장하거나 복사한 내용은 회수할 수 없습니다. 공개 요청마다 소유자의 활성 상태와 메모 이용 권한, 현재 폴더 트리, 원본의 소유자와 위치를 다시 검사합니다. 삭제되거나 허용 범위 밖으로 이동한 원본은 공개 응답에서 제외합니다.

범위 밖의 내부 링크는 비공개 표시로 바꿉니다. 글의 일반 문장과 코드에 직접 적은 내용은 게시자가 검토해야 합니다. 이전 게시본에 인용된 링크 문자열은 복사본 갱신 전까지 남을 수 있습니다. 화면의 링크 탐색은 현재 공개 범위 안에서만 가능합니다.

## 읽기와 저장 경계

- 폴더 탐색, 검색, 백링크, 그래프와 목차를 제공합니다. 문서를 열면 기존 문서를 유지하며, 공간이 부족하면 이전 문서를 제목 패널로 접습니다. 공개 방문자에게 편집이나 내 위키 메뉴를 표시하지 않습니다.
- 공개 위키 하나당 메모 200개, 이미지 64개, 폴더 200개, 전체 20MiB를 제한합니다. 본문은 128KiB, 이미지 저장 표현은 512KiB, 업로드 묶음은 1MiB 이내입니다.
- 본문은 최대 8개씩 선택 문서를 우선 읽고, 이후 제한된 동시 요청으로 불러옵니다. 참조 이미지는 필요한 때만 읽으며 같은 요청을 합치고 작은 메모리 캐시를 사용합니다.
- 서버 API만 접근하는 별도 Firestore 컬렉션에 복사본을 저장합니다. 개인 메모의 Firestore Rules 권한을 공개로 바꾸지 않습니다. 완성된 임시 버전만 원자적으로 활성화합니다.
- 응답은 `no-store`이며 본문·이미지는 화면 수명 범위의 메모리에만 보관합니다. 주소·버전·권한 변경 감지 시 이전 범위를 폐기합니다. 공개 상태는 포커스 복귀와 45초 주기로 재확인합니다.
- 공개 링크는 원본 첨부파일의 다운로드 권한을 부여하지 않습니다. 허용한 래스터 이미지 복사본만 미리 보고, SVG 등 안전하지 않은 형식은 표시하지 않습니다.
- Markdown 원문을 유지하고 기존 HTML은 안전한 렌더러로 표시합니다. Obsidian의 모든 플러그인·테마·확장 문법과 완전한 호환을 보장하지는 않습니다.

## 배포 구조

새 환경변수, secret, Firebase Rules/index 배포나 일괄 데이터 마이그레이션은 필요하지 않습니다. 기존 Firestore REST 서버 자격과 Auth/App Check 설정을 사용하며, root·slug·UI 설정 문서는 사용자의 명시적 동작으로 생성됩니다. 새 컬렉션은 기존 Rules의 기본 거절 규칙으로 브라우저 직접 접근이 차단됩니다.

Vercel Hobby의 API 함수 12개 한도를 유지하기 위해 UI 설정 처리기는 `api/_workspace-preferences.js` 내부 모듈로 둡니다. 요청은 `POST /api/vault-integrity?resource=workspace-preferences`에서 분기하며, 전용 요청 marker·same-origin·App Check·활성 UID·2KiB 본문 제한을 그대로 검사합니다. 일반 integrity action과 서로 대체할 수 없습니다. UI 설정은 폭과 접힘 여부만 저장하고 개인 메모·키·본문을 포함하지 않습니다. `security:functions-guard`는 배포 API 개수가 12개를 넘으면 실패합니다.
