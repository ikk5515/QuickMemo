# 위키 읽기와 폴더 공개

`/wiki`는 로그인한 계정의 전체 개인 메모를 읽는 화면입니다. 기존 암호화 키를 잠금 해제해야 하며, 공개 여부와 관계없이 본인이 소유한 활성 메모를 탐색할 수 있습니다.

메모 화면의 폴더 작업 메뉴에서 **폴더 위키 공개…**를 선택하면 하위 폴더를 포함한 공개 목록을 확인할 수 있습니다. 체크박스를 선택하고 **위키 게시**를 누르면 `/wiki/public/:wikiId` 링크를 생성합니다. 해당 링크는 로그인 없이 읽을 수 있습니다. 다른 폴더, 다른 소유자의 메모, 휴지통 항목은 포함하지 않습니다.

공개 내용은 게시 시점의 별도 복사본입니다. 원본의 암호화 본문과 키는 그대로 유지됩니다. 공개 폴더의 메모를 수정한 뒤 **공개 내용 업데이트**로 같은 링크에 반영합니다. **공개 중지**는 기존 링크의 접근을 즉시 차단합니다. 이미 방문자가 저장하거나 복사한 내용은 회수할 수 없습니다.

공개 요청마다 소유자의 활성 상태와 메모 이용 권한, 현재 폴더 트리, 각 원본의 소유자와 위치를 다시 검사합니다. 원본이 삭제되거나 선택 폴더 밖으로 이동하면 공개 목록과 본문 요청에서 제외합니다. 공개 메모의 내부 링크 중 범위 밖의 대상은 비공개 표시로 바꿉니다. 공개 글의 일반 문장과 코드에 직접 적은 내용은 게시자가 검토해야 합니다. 이미 게시된 글에 인용된 이전 링크 문자열은 저장된 복사본에 남을 수 있습니다. 읽기 화면에서는 현재 공개 범위 밖의 링크를 숨기며, 원문 복사본까지 갱신하려면 공개 내용을 다시 게시합니다.

읽기 화면은 폴더 탐색, 제목·본문·목차 검색, 본문 아래 백링크, 현재 문서의 그래프와 계층형 목차를 제공합니다. 내부 링크를 따라가면 이전 글과 스크롤 위치를 유지하며 오른쪽에 최대 6개 글을 쌓습니다. 좁은 화면에서는 현재 글과 이전 글 이동 버튼을 표시합니다.

## 저장 및 전송 경계

- 공개 위키 하나당 메모 200개, 이미지 64개, 폴더 200개, 전체 20MiB를 제한합니다.
- 메모 본문은 128KiB, 이미지의 저장 표현은 512KiB, 업로드 묶음은 1MiB 이내입니다.
- 문서 본문은 최대 8개씩 나누어 읽고, 선택 문서를 먼저 읽은 뒤 나머지를 제한된 동시 요청으로 불러옵니다.
- 공개 복사본은 서버 API만 접근 가능한 별도 Firestore 컬렉션에 저장합니다. Firestore Rules의 개인 메모 권한을 공개로 바꾸지 않습니다.
- 전송이 완성된 임시 버전만 원자적으로 게시합니다. 부분 업로드는 방문자에게 노출되지 않습니다.
- 응답은 `no-store`이며 공개 읽기 화면의 본문은 메모리에만 보관합니다. 화면 전환·공개 범위 변경·공개 중지 감지 시 이전 범위를 폐기합니다. 열린 화면은 포커스를 되찾거나 주기적으로 공개 상태를 다시 확인합니다.
- 공개 링크가 자동으로 원본 첨부 파일의 다운로드 권한을 부여하지 않습니다. 공개 범위 안에서 허용한 래스터 이미지 복사본만 미리 봅니다.

## Markdown

메모는 Markdown 원문을 유지합니다. 위키 링크, 일반 Markdown 링크, 제목/블록 참조, 코드 블록, 표, 체크리스트, 중첩 목록, 각주, 콜아웃, 강조 표시를 읽기 화면과 함께 검증합니다. 기존 HTML 메모는 안전한 읽기 렌더러를 사용합니다. Obsidian의 모든 플러그인·테마·확장 문법과 완전한 호환을 보장하는 기능은 아닙니다.
